# Local signed OTA failure fixtures

`scripts/native-ota-fixtures.mjs` builds and selects local HTTPS fixtures for installed-app probes. It invokes the production `mobile-release.mjs` packager and its build-contract/key/channel checks, then makes only the intentional negative-fixture mutations. It never modifies the input build, uploads files or generates a persistent private key. Signing uses the temporary key referenced by ignored `.native-build/ota-test-config.json`; the wrong signer exists only in process memory.

## Build and select

Use a native build compiled with that config's two local channels and public JWK. A build with disabled production channels correctly fails packaging. The parent builds `.native-build/ota-dist-round3` separately; this script does not run Vite.

```sh
node scripts/native-ota-fixtures.mjs build \
  --dist .native-build/ota-dist-round3 \
  --out .native-build/ota-fixtures-round3 \
  --native-version 1.0.0 --sequence-base 1000
node scripts/native-ota-test.mjs serve .native-build/ota-test-config.json
node scripts/native-ota-fixtures.mjs select \
  --out .native-build/ota-fixtures-round3 --platform ios --case validA
```

Replace `ios` with `android` for the emulator. Keep the configured server running; restart an older server process to pick up network fault support. The simulator/emulator must trust the temporary local TLS CA. Changing the channel selection copies the ZIP first, then atomically replaces only that platform's manifest. Nothing is publicly deployed. Pick a fresh output directory and a sequence base above the installed high-water value for each repeat run; the builder refuses to overwrite a previous fixture suite.

`checks.json` records the source revision/index hash, marker, manifest, signature validity, actual archive hash validity, expiry, native compatibility and archive size for every platform/case. All 18 cases are independently checked with the pinned public key before the builder succeeds. RSA-PSS signatures and ZIP timestamps can differ between builds; scenario behavior, markers and sequence ordering are reproducible.

| Case | Sequence offset | Expected installed behavior |
| --- | ---: | --- |
| `validA` | +1 | Download/stage; activate only on next launch; marker `validA`; ready acknowledged. |
| `validB` | +2 | Same, with marker `validB`. |
| `intentionalRollback` | +3 | Healthy A's exact HTML/game content, newly signed at a higher sequence; marker `validA`. This is an intentional content rollback, not replay of A's old manifest. |
| `expired` | +4 | Valid signature and ZIP; manifest already expired; no download or activation. |
| `incompatible` | +5 | Valid signature and ZIP; native bounds `999.0.0`; reject on the actual `1.0.0` wrapper. |
| `wrongSignature` | +6 | Signed with another ephemeral RSA key; reject before download. |
| `corruptZip` | +7 | Correctly signed original archive hash; a byte of served ZIP changed; native checksum rejection. |
| `brokenStartup` | +8 | Signature/hash/bounds valid; HTML never starts game or acknowledges readiness; native watchdog must restore the last healthy bundle. |
| `orphan` | +9 | Valid downloadable bundle reserved for a harness-created pending bundle without an application pending pointer; next healthy launch's cleanup must delete it. |

The runtime marker is `window.__nativeOtaFixture`, also `document.documentElement.dataset.otaFixture` and a console message. A marker proves content identity only: pair it with native bundle ID/status, game readiness, durable save state and later-launch observations. For bad startup, the parent must wait through the configured readiness timeout and prove the previous healthy game actually resumes. Checks generated by this builder do not prove those installed-app outcomes.

## Orphan cleanup probe

Publish the orphan archive without changing the channel:

```sh
node scripts/native-ota-fixtures.mjs select \
  --out .native-build/ota-fixtures-round3 --platform ios --case orphan \
  --archive-only true
```

The command returns `url`, `checksum` and `bundleId`. At a healthy idle menu, the installed-app harness calls the actual native updater `download({url, checksum, version: bundleId})` and records the returned internal ID/status. Do not call `set`, `next` or write the application's pending pointer. Relaunch, reach readiness and check that `list()` no longer contains that orphan while active/previous healthy bundles and save state survive. Keep the channel on an already-consumed healthy sequence while probing this case. This does not test arbitrary filesystem deletion or total retention: cleanup is intentionally limited to abandoned `pending` bundles, at most eight attempts per launch; native code owns successful fallback and failed-bundle retention.

## Interrupted and delayed transfers

These controls affect ZIP GET requests for just one platform; manifests and HEAD requests remain normal. They persist until reset. The server logs the fault and requested path.

```sh
node scripts/native-ota-fixtures.mjs network --platform ios --mode interrupt --after-bytes 32768
node scripts/native-ota-fixtures.mjs network --platform ios --mode delay --delay-ms 15000
node scripts/native-ota-fixtures.mjs network --platform ios --mode normal
```

Use a fresh compatible fixture sequence for retry tests. `interrupt` closes a partial response while advertising its full Content-Length; `delay` waits before sending headers/body, up to 60 seconds. Check actual app/play responsiveness and persistence during the transfer, then reset to `normal` and prove later recovery. The server never exposes its internal dotfile fault controls over HTTP.

## Verification scope

`node --test scripts/native-ota-fixtures.test.mjs` builds both platforms against a minimal native contract, verifies all nine intended cases, checks marker/boot contents and unchanged source files, exercises archive-only orphan publication, and runs a real local HTTPS server to prove truncated transfer rejection, delayed successful transfer, unaffected manifest delivery and hidden control files. `node --test scripts/mobile-release.test.mjs scripts/native-ota-fixtures.test.mjs` also reruns the shared packager contract tests.

Installed iOS/Android results belong in their probe reports. These fixture checks are preparation for that evidence, not a substitute for playing and relaunching the installed apps.
