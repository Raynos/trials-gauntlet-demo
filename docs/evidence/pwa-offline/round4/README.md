# PWA offline — round 4 evidence: headers, versioning, and the iOS install surface (ask 58)

## 1. `vercel.json` — the user's call, applied

> "stop serving `/models/**` and `/art/**` with `max-age=0, must-revalidate` … version / content-hash
> them and serve them with a long cache — maybe max-age one month, so that it does get garbage
> collected eventually."

| path | before | after | why it is safe |
|---|---|---|---|
| `/assets/(.*)` | 1 year immutable | unchanged | hashed filenames |
| `/models/(.*)` | **`max-age=0, must-revalidate`** | **1 year immutable** | `/models/<16hex>/<name>-<16hex>.glb` — content-addressed twice |
| `/art/(.*)` | **`max-age=0, must-revalidate`** | **`max-age=2592000`** (30 days) | every URL now carries `?v=<8 hex of the file>` |
| `/fonts/(.*)` | **`max-age=0, must-revalidate`** | **`max-age=2592000`** | three files, stable, and the worker holds them anyway |
| `/art/manifest.json`, `/art/worldmap/worldmap.json` | — | `max-age=0, must-revalidate` | they hand out the versions; a month-old index pins a month-old pack |
| `/`, `/index.html`, `/offline.html` | `no-store` | `no-store` | the worker owns the document |
| `/sw.js`, `/load-manifest.json` | `max-age=0, must-revalidate` | **`no-store`** | these are how a new build is discovered and named |
| COOP `same-origin` + COEP `require-corp` | every response | **unchanged** | see below |

**The isolation is asserted, not assumed.** A response replayed from Cache Storage carries the headers
it was stored with, and the harness's 5 µs `performance.now()` depends on cross-origin isolation
(`vite.config.ts` `ISOLATION_HEADERS`, plan risk §9.4). `offline.coldStartPlayable` now fails unless
`crossOriginIsolated === true` on the offline cold start.

## 2. Versioning without renaming 122 files

- **Art (122 assets):** `public/art/manifest.json` gained a `v` per asset — 8 hex of the file's own
  bytes — and `src/ui/art.ts` resolves every entry to `art/<path>?v=<v>`. `assets/art/build.mjs` writes
  it from now on; the 122 already in the tree were stamped from their bytes on disk (the pipeline needs
  its gitignored raw art to re-run).
- **World map (13 plates):** not in any manifest, so the version is the build's own hash of
  `public/art/worldmap/`, compiled in as `__WORLDMAP_V__` and appended by `src/ui/worldMap.ts`
  (`worldPlateSrc` / `regionPlateSrc` / `worldMapIndexSrc`).
- The service worker's `cache.match` therefore **stopped** passing `ignoreSearch`: with the version in
  the query, ignoring the query would serve last month's plate for a new URL. It still passes
  `ignoreVary` — see round 1, that one is load-bearing.

**Known trade, stated:** one changed art file changes one URL (good), but the worker's *static* cache is
keyed by a hash of all of `public/art` + `public/fonts`, so an art deploy still costs the player the art
pack again. A JS-only deploy costs nothing of it — which is the case that actually happens, and which
the update-boot measurement below exercises.

## 3. The iOS install surface

- **`apple-touch-startup-image` × 28** (14 device pixel sizes × portrait and landscape), generated by
  `node assets/art/splash.mjs` into `public/art/splash/` — 1.16 MB total, the loader's own plate
  (`#07080a` ground, the amber leading edge, the italic wordmark) on a flat background. iOS does not use
  the manifest's `background_color` for a home-screen app; with no startup image it shows **white** until
  the first paint, which is most of what "I opened it and it didn't load" looked like. The `<link>` tags
  are in `index.html` with the `(device-width) and (device-height) and (-webkit-device-pixel-ratio) and
  (orientation)` media queries iOS matches on.
- **`apple-touch-icon` at 152 and 167** as well as 180 (the iPad sizes iOS would otherwise downscale).
- The launch images are listed in `dist/load-manifest.json` (phase `title`) but are deliberately **not**
  fetched by the boot: iOS downloads them itself at "Add to Home Screen" and stores them, so spending
  1.16 MB of the player's first load on them would buy nothing.
- `index.html` now carries a comment saying iOS ignores the manifest's `orientation: landscape` (a
  home-screen app follows the rotation lock), so nobody "simplifies" the rotation handling away.

**Only a human can judge the result** — headless Chromium is not iOS Safari. That is the HR row.

## 4. Bytes over the wire — cold boot vs update boot

Measured in the HTTP server (`harness/e2e/offline.mts`), one online load then a new build under the same
origin, adopted at the very start of the loading screen:

| | bytes | requests |
|---|---|---|
| cold first boot | **39 010 615** | 184 |
| **update boot** | **39 829** | 11 |

**0.10 % of a cold boot.** `/sw.js` (31 593 B, served uncompressed by the test middleware — the real one
is gzipped) and `/` (8 236 B) are the whole cost; `load-manifest.json`, `index.html`, `offline.html`,
`manifest.webmanifest` and `model-catalog.json` came back `304`, and **0 bytes of models** left the
origin. The immutable cache survived the deploy and `activate` pruned instead of wiping.
