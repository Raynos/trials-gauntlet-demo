# Local Blender art delivery rebuild

This runner rebuilds the accepted component pipeline without editing the review catalog, game code or publishing anything. It writes the existing recipe intermediates, so run it in the shared checkout only while other art builders are stopped. Raw appearance exports remain large.

Inspect the exact command graph and missing inputs first, from any working directory:

```sh
python3 /absolute/repo/prototypes/hero-garage/tools/build-art-delivery.py --stage 28
python3 /absolute/repo/prototypes/hero-garage/tools/build-art-delivery.py --stage 29
```

Add `--execute` to run. Choose a Blender executable with `--blender /path/to/blender` or `BLENDER`; the default is the local macOS Blender installation. Each command uses an argument array and Blender's nonzero Python-error exit code. Execution always runs with repository root as cwd.

## Inputs and stages

Frozen seed inputs are `assets/blender/source/rider-street.blend`, `public/assets/street01-rider-garment-repair.glb`, `public/assets/street01-head-groom.glb`, and `art/denim-refine/source-removal-triangles.json` (the latter three relative to the hero-garage prototype). Missing seeds fail preflight; the runner does not silently substitute other assets or rebuild the approved groom.

Both stages rebuild identity, continuous hoodie source, R28 cloth finish, footwear, cuff3 gloves and accepted denim. The glove extractor explicitly generates sleeve-boundaries.json from the freshly rebuilt R28 editable shirt before cuff3 build; footwear/glove removal manifests are regenerated by their builders. Accepted denim generates its editable source before the R29 texture bake.

Stage 29 additionally builds the accepted neck-fit-v2 clothing and hidden neck-flange index trim, then the dedicated denim texture donor. It requires `art/denim-texture/assemble.py` with `--base` and `--out`; preflight refuses stage 29 until that worker-supplied interface exists. Stage 28 omits both changes. All component assemblers receive explicit base/output arguments where supported; their outputs form one ordered chain.

Final output: `public/assets/street01-rider-delivery-raw.glb`. This is a rider asset, not the bike or a game integration. Passing a different stage overwrites that final delivery filename; stage-specific footwear/glove intermediates retain their stage number.

## Lossless packing and evidence

Add `--pack` to produce `public/assets/street01-rider-delivery-lossless.glb`. The current packer requires Node, prototype npm dependencies, Python3, and the specific Blender5.2 macOS meshoptimizer libraries; the runner preflights those paths. Choosing another Blender does not make this optional packer portable. Its independent Three.js decoder verifies exact decompression of retained buffers.

Every executed run writes `art/delivery/runs/<UTC-time>-<id>/manifest.json`, per-step logs, Blender version output, source/recipe/input/output SHA256 values, and optional packing proof. Failure preserves logs and marks the manifest failed; do not use an old final file as evidence of a successful failed rebuild. No resume/cache skipping is implemented.

A successful manifest says `built-not-visually-approved`. Re-render matched views and all six clips before accepting the delivery; numeric reconstruction and lossless packing are not visual approval. Source seeds are checked unchanged at the end.

All12 matched Three.js PNG comparisons (six clips, full and face views) were byte identical after lossless packing. This proves reproduction and packing preservation, not final art quality.
